Added `b2c security scan`, `b2c security rules`, and `b2c security baseline` (preview) to find security problems in cartridge code: SFRA and SiteGenesis POST routes without CSRF checks, `server.replace()` overrides that drop security middleware, GET routes that change data, mass assignment, object query injection, open redirects, file paths and upload names chosen by the client, weak cryptography, hardcoded credentials, insecure cookies, personal data in logs, and dynamic code. Site data in the project is checked too: OCAPI settings that use the demo client ID `aaaaaaaaaaaaaaaaaaaaaaaaaaaaaa` or grant every resource, plaintext service passwords and `http://` service URLs, service communication logging, credentials in preferences, secret attributes that aren't the password type, and Business Manager CSRF exemptions. Route rules compose SFRA routes across the cartridge path. Findings in SFRA and SiteGenesis base cartridges are reported and tagged. Scans run locally with no instance or credentials, support inline suppressions and baselines, and can write SARIF for GitHub code scanning. The SDK exposes the scanner as `@salesforce/b2c-tooling-sdk/security` and a project index of controllers, routes, pipelines, hooks, Custom APIs, and job steps as `@salesforce/b2c-tooling-sdk/project-index`.
